# Эмулятор командной строки

Учебный проект по дисциплине «Конфигурационное управление».
Вариант №16: эмулятор оболочки UNIX-подобной ОС с виртуальной файловой
системой (VFS). Язык — Python 3.10+, внешние библиотеки не нужны.

## Общее описание

Эмулятор — консольное приложение (REPL). VFS загружается из XML-файла
в память; все команды работают только с этой моделью, файл на диске
никогда не изменяется. Приглашение содержит имя VFS и текущую папку:
`demo:/home/alex$`. Перед выполнением команды раскрываются переменные
окружения реальной ОС (`$HOME`, `${HOME}`); поддерживаются кавычки.

Команды: `ls`, `cd`, `du`, `find`, `chmod`, `exit`, служебная `vfs-info`.

## Структура репозитория

```text
src/
  emulator.py        точка входа, REPL, выполнение строки
  cmdline.py         разбор строки и раскрытие переменных окружения
  config.py          параметры командной строки и JSON-конфигурация
  script.py          стартовый скрипт
  session.py         состояние сеанса (VFS, текущая папка)
  vfs.py             модель VFS, загрузка XML, разбор путей
  options.py         разбор опций команд (-l, -la, --)
  commands.py        реестр команд, exit, vfs-info
  fs_commands.py     ls, cd, du, find
  chmod_command.py   chmod
tests/
  test_stage1..5.py  unit-тесты
  scripts/           стартовые скрипты эмулятора
  configs/           примеры конфигурационных файлов
vfs/                 примеры VFS (invalid/ — неверные файлы)
run*.bat, test_*.bat скрипты запуска для Windows
```

## Настройки (параметры запуска)

| Параметр | Назначение |
| --- | --- |
| `--vfs ПУТЬ` | XML-файл VFS |
| `--script ПУТЬ` | стартовый скрипт |
| `--config ПУТЬ` | конфигурационный файл JSON |

Конфигурационный файл содержит те же `vfs` и `script`:

```json
{"vfs": "vfs/demo.xml", "script": "tests/scripts/stage5_start.txt"}
```

Значения из командной строки важнее значений из файла. При запуске
печатаются все параметры и источник каждого. Ошибки конфигурации,
VFS или чтения скрипта сообщаются, код возврата 2.

**Стартовый скрипт.** Пустые строки и строки с `#` пропускаются. Ввод
и вывод показываются как диалог. На первой же ошибке команды
выполнение останавливается, печатается номер строки, код возврата 1.
Если скрипт закончился без `exit`, эмулятор переходит в
интерактивный режим.

## Формат VFS (XML)

```xml
<vfs name="demo">
  <dir name="home" mode="755">
    <file name="a.txt" mode="644">текст</file>
    <file name="b.bin" encoding="base64">AAEC/w==</file>
  </dir>
</vfs>
```

- `name` у `<vfs>` — имя в приглашении (по умолчанию имя файла);
- `mode` — права в восьмеричном виде (по умолчанию 755 для каталога,
  644 для файла);
- двоичные данные задаются с `encoding="base64"`.

Ошибки загрузки: файл не найден, неверный XML, корень не `<vfs>`, нет
`name`, неверные права или base64, повторяющиеся имена.

Примеры: `vfs/minimal.xml` (один файл), `vfs/files.xml` (несколько
файлов), `vfs/deep.xml` (четыре уровня), `vfs/demo.xml` (основной),
`vfs/locked.xml` (каталоги без прав), `vfs/invalid/*.xml` (ошибки).

## Команды

Пути абсолютные и относительные, поддерживаются `.` и `..`.

| Команда | Описание |
| --- | --- |
| `ls [-a] [-l] [путь...]` | содержимое каталога или сведения о файле; `-a` — скрытые файлы, `-l` — права и размер |
| `cd [путь]` | переход в каталог; без аргумента — в корень VFS |
| `du [-a] [-s] [-h] [путь...]` | размер в байтах; `-a` — и файлы, `-s` — только итог, `-h` — вид `1.5K` |
| `find [путь...] [-name шаблон] [-type f\|d]` | поиск по дереву, шаблон как в shell (`*.txt`) |
| `chmod [-R] режим путь...` | права: восьмеричные (`644`) или символьные (`u+x`, `go-w`, `a=rx`, `u=rwx,go=r`); `-R` — рекурсивно |
| `vfs-info` | служебная: сводка и дерево VFS |
| `exit` | завершение работы |

**Права доступа.** Проверяются биты владельца: для `ls`, `du`, `find`
каталог должен быть доступен на чтение (`r`), для `cd` — на вход (`x`).
Иначе сообщается `Отказано в доступе`. `chmod` меняет права только в
памяти.

Ошибки (неизвестная команда, неверные опции и аргументы, нет такого
пути, незакрытая кавычка) печатаются в виде `команда: сообщение`.

## Запуск и тесты

```bat
run.bat                                  интерактивно, VFS demo
python src\emulator.py --vfs vfs\demo.xml --script tests\scripts\stage5_start.txt
python src/emulator.py --config tests/configs/demo.json
run_tests.bat                            unit-тесты
python -m unittest discover -s tests     то же без bat
```

Скрипты проверки по этапам (запускать двойным щелчком или из консоли):

| Скрипт | Что проверяет |
| --- | --- |
| `run_stage2.bat` | все параметры командной строки, конфигурация, ошибки |
| `test_vfs_minimal.bat`, `test_vfs_files.bat`, `test_vfs_deep.bat` | варианты VFS |
| `test_vfs_errors.bat` | ошибки загрузки VFS |
| `run_stage3.bat` | стартовый скрипт этапов 1–3, ошибки команд |
| `run_stage4.bat` | `ls`, `cd`, `du`, `find`, права доступа, ошибки |
| `run_stage5.bat` | `chmod`, ошибки |

## Примеры

```text
demo:/$ ls -l
drwxr-xr-x      0 bin
drwxr-xr-x      0 home
-rw-r--r--     52 readme.txt
drwx------      0 secret
demo:/$ cd home/alex
demo:/home/alex$ du -sh .
92B	.
demo:/home/alex$ find . -name "*.txt"
./docs/plan.txt
./notes.txt
demo:/home/alex$ chmod u=rw,go= notes.txt
demo:/home/alex$ ls -l
drwxr-xr-x      0 docs
-rw-------     21 notes.txt
demo:/home/alex$ cd /secret
demo:/secret$ cd /
demo:/$ chmod 000 secret
demo:/$ cd secret
cd: secret: Отказано в доступе
demo:/$ foo
foo: команда не найдена
demo:/$ exit
```
